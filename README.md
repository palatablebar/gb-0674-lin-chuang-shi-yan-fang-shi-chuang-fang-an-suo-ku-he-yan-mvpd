# 临床试验访视窗与方案锁库核验

给临床试验数据管理员使用。按入组基准计算访视半开窗，方案修订按受试者生效时间选版；漏访不可用复检伪填。

八个业务模块：记录采信、方案版本、访视排窗、偏离复核、复检裁决、澄清裁决、锁库检查、冻结归档。

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
```

访问 http://localhost:18243 。启动直接载入现场脏批。切换干净样例和旧编码样例可对照核验。清批20个虚构受试者、40次应访视及5次复检，可锁库冻结。现场脏批包含窗末偏离、缺首次访视、错误复检引用及方案不符，必须处理后才能冻结。

各模块页面对应 `/<模块英文名>`，各模块执行入口为 `POST /api/<模块英文名>`，不传参即可独立演示。完整运行 `POST /api/runs` 支持 `dataset`（dirty/clean/legacy）、`csv_text`、`queries`、`corrections` 与 `overrides` 参数。批次历史 `GET /api/runs`，详情 `GET /api/runs/{run_id}`。

同输入与规则版本生成相同批号，只保留一条批次。复核入口 `POST /api/runs/{run_id}/review` 提交当前 `revision`，陈旧提交409。归档包只有一个下载入口 `GET /api/export/{run_id}`，含证据、澄清记录和运行摘要。原始隔离在页面同屏显示。

SQLite使用命名卷，容器重启后保留历史。要重建演示可在Compose中改用新的卷名称，保留旧卷。

源码在 `app/`，样例在 `sample_data/`，测试在 `tests/`；定义见 `docs/DATA-DICTIONARY.md`，模块和边界测试对应关系见 `docs/DEPTH.md`。输入上限2MB，属于离线复核工具。

采信页支持上传或粘贴CSV。完整源字节与参数随批次持久化，跨页通过run_id读取同一结果。`POST /api/runs/{run_id}/rerun` 读取该批不可变输入快照重新计算，规则未变时批号不变。切换另一示例则创建或复用另一批次。

## 澄清问题裁决

锁库前未关闭的澄清问题按性质分两类，今天形成唯一可锁库清单：

| 类别 | 判据 | 冻结判定 |
|---|---|---|
| 关键事实（key） | 质疑访视日期、检验值、单位、版本、访视编号等，可能改变方案选版、访视窗、偏离或复检结论 | 未关闭即**阻断**；关键事实未核实不冻结 |
| 格式待办（format） | 仅备注、注释等格式问题 | 可在标注后**随批冻结** |

统一状态：

- 每条问题得到 `freeze`（阻断 / 随批冻结 / 已关闭）、原因码、原始提问、全部回复。
- 同一批问题生成 `clarify_digest`，方案行、窗口行、偏离、复检、锁库清单行与冻结凭证都引用同一摘要。
- 每条访视给出冻结状态、关键问题、关联问题与全部阻断原因；`/clarify` 页面同屏可见。
- 有任一阻断问题或问题状态冲突（同编号内容冲突、已关闭无回复、目标记录缺失或已被隔离）时锁库状态为“待处理”，冻结凭证下载409。

关闭与失效：

- `POST /api/clarify/reply` 追加回复（原始提问与全部回复只追加），可按 `corrections` 提交已核实更正并整体重算；旧结论作废并指向新批次，旧版仍可追溯但不可作为冻结依据。
- 只接受已关闭关键澄清授权过的更正；更正后记录若无法通过方案校验则整批失败，旧版仍为当前结论。
- 同一回复重试幂等：不新增处理、不新增批次；重复点击不会产生分支结论。
- 示例清单 `GET /api/clarify/sample`，澄清页可一键载入脏批演示。
